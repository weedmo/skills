스킬은 3계층으로 나뉩니다. ① 이 저장소의 skills/ — weed-harness 공통 루프 런타임과 Claude Code·Codex 공용 design-map(단 setup은 Claude 전용), ② ~/.claude/skills/ — 플러그인과 무관하게 로컬에 직접 설치된 스킬, ③ superpowers·unlazy 등 다른 플러그인이 제공하는 스킬(이 문서 범위 밖).

훅은 이 저장소의 hooks/에 스크립트로 보관되고, settings.json(사용자 전역)과 hooks.json(플러그인)에 이벤트별로 등록되어 실행됩니다.

1. 리포 플러그인 — 하나의 repo, loop별 플러그인

repo는 하나(weedmo/skills)로 두고 세 패키지를 발행합니다 — weed-harness(root, 공통 루프 런타임 + Claude Code setup·hooks·HUD, 모든 플랫폼 필수) · matt-loop(plugins/matt-loop/) · auto-loop(plugins/auto-loop/, 자율 루프). 두 루프는 목적과 루프 그래프만 다르고, 진행 페이지·모델 라우팅·완료 게이트는 weed-harness에서 공통으로 가져옵니다. Codex marketplace에도 세 플러그인이 모두 노출됩니다.

🧱 공통 루프 런타임 — weed-harness (skills/, 모든 플랫폼)

스킬분류역할
loop-report진행 페이지 긴 위임 루프의 진행 페이지를 만들고 전달. assets/shell.html(디자인 시스템, 진행 상황 헤더·퍼센트·ETA·막힘, 결과 패널, 자동 새로고침) + 각 루프의 view.html + 데이터 JSON을 render.py가 조립. 전달은 deliver.py probe | publish | show 스크립트가 맡는다: Orca artifact 링크 → Orca 내장 브라우저 탭 → 경로 순이며 한 실행 동안 고정, 상태는 delivery.json에 스크립트만 기록. 호출 스킬은 스크립트를 실행하고 답을 전달할 뿐이다.
model-routing라우팅 Fast / Default / Deep / Max 티어 표 하나 — Codex spawn_agent, Claude Code agent, OpenCode, Orca worker-start 플래그별 정확한 model/effort 쌍, 디스패치 규칙, 에스컬레이션 사다리. 각 루프는 자기 역할을 이 티어에 매핑만 한다.
loop-gates완료 게이트 루프가 unlazy 스킬(Leonxlnx/unlazy, 벤더링하지 않고 npx로 설치)을 쓰는 규약 — 작업 단위별 GATES.md, 코디네이터가 직접 --reverify, 재시도 2회 후 핸드오프, Orca 오케스트레이션과의 경계.

🔁 자율 루프 — auto-loop 플러그인 (plugins/auto-loop/skills/)

스킬분류역할
autocode루프 가설 주도 병렬 코드 개선 루프. 고비용 티어의 Strategist가 가설(맞으면/틀리면 다음 행동 포함)을 세우고, 난이도별로 라우팅된 Experimenter가 worktree에서 동시에 구현·guard, 측정은 직렬. 결과 1건마다 가설을 갱신하고, 메트릭 추이·프론티어·실험 기록을 담은 실험 보드를 loop-report로 매 상태 변화마다 재발행. 종료는 loop-gates(unlazy) 재검증으로 확정. 채택된 변경은 사용자 checkout을 옮기지 않고 .autocode/worktrees/best의 autocode/<slug> 브랜치에 keep마다 측정치를 담은 squash 커밋 1개로 쌓이고, 종료 시 시작 브랜치로 PR을 연다(병합은 사람). 서브커맨드: init [--spec <path>] / run [--pr <base> | --no-pr] / status / resume — --spec은 확정된 design-map spec의 metric 블록으로 인터뷰를 선채운다.

📝 설계·설정 (weed-harness)

스킬분류역할
setup유지관리 Claude Code 전용. 터미널 UI + 기본 설정만 담당 — statusLine HUD 설치, 커스텀 훅(language-rule, auto-update) 등록. 스킬 설치는 하지 않으며 멱등이라 반복 실행해도 안전.

🤖 크로스 에이전트 — matt-loop 플러그인 (plugins/matt-loop/skills/)

Codex, OpenCode, Claude Code, Gemini CLI에 설치할 수 있습니다. OpenCode에서는 별도 task-tier agent가 자동 모델 라우팅을 제공합니다.

스킬분류역할
matt-autoCodex Matt Pocock 메인 플로우(grilling 인터뷰 → spec → 티켓 → 티켓별 구현)를 처음부터 끝까지 지휘. 결정 위임자가 일상 질문에 답하고 인터뷰 게이트 하나만 사람이 승인. 모델은 model-routing 티어로 자동 라우팅, 결정 그래프와 티켓 보드는 interview-report → loop-report로 발행, 병렬 웨이브만 Orca 워커. --spec <path>로 확정된 design-map spec을 받으면 그 결정은 읽기 전용 design 단계가 되고 인터뷰는 열린 질문만 묻는다.
interview-report보고 matt-auto의 결정 그래프 뷰(assets/view.html + validate.py) — 스테이지, 편집 가능한 결정 노드와 <slug>.edits.json 왕복, 티켓 웨이브, 리뷰·PR 레인. 페이지 조립과 전달은 loop-report.
pr-babysitPR 열린 PR 하나를 격리된 worktree에서 CI와 리뷰가 완료될 때까지 관리. 명시적으로 요청하지 않으면 merge하지 않음.
resolving-merge-conflictsGit 진행 중인 merge/rebase 충돌을 해결. OpenCode에서 단독 호출하면 deep 모델로 자동 라우팅.

2. 로컬 스킬 (~/.claude/skills/)

플러그인 배포와 무관하게 직접 설치된 스킬. 2026-07-30 정리에서 미사용 스킬 5개(browse, qa, scrape, diagram, karpathy-guidelines)는 skillOverrides로 비활성화되어 4개만 활성 상태입니다.

스킬출처역할
orca-cliOrca orca CLI로 Orca가 관리하는 worktree·터미널·자동화·내장 브라우저를 조작. 다른 에이전트로의 완전한 핸드오프(handover)에도 사용.
orchestrationOrca Orca 멀티에이전트 조율 — 스레드 메시지, ask/reply 블로킹 플로우, 태스크 DAG, 의사결정 게이트, 코디네이터 루프.
computer-useOrca Orca의 computer-use CLI로 로컬 데스크톱 앱 창을 접근성 트리·스크린샷·안전한 UI 액션으로 검사·조작.
graphify독립 모든 입력(코드·문서·논문·이미지)을 영속 지식 그래프로 변환. graphify-out/이 있으면 코드베이스 질문을 그래프 쿼리로 먼저 처리해 토큰 절약. pip 패키지 graphifyy로 배포.

3. Hooks (hooks/)

이벤트에 자동 반응하는 스크립트 3개. OMC 훅(omc-skill-filter), Codex 리뷰 훅(codex-task-review), devlog 계열(devlog-hook, tsg-bash-failure), merge-conflict-trigger, gstack-skill-filter는 정리 완료로 삭제됐습니다.

훅이벤트역할
graphify-claudemd-inject.shPostToolUse: Skill /graphify 스킬 실행 후 프로젝트 CLAUDE.md에 graphify 운용 섹션을 자동 주입.
auto-update.shSessionStart 필수 스킬 자동 업데이트 — PyPI에 graphifyy 신버전이 있으면 업그레이드 후 claude·codex 양쪽에 스킬 재설치, superpowers 플러그인 업데이트(best-effort), weed-plugins 세 플러그인 업데이트, codex 네이티브 설치가 없으면 ~/.codex/skills에 공통 런타임과 두 루프 스킬을 재동기화, unlazy 스킬 보장 및 하루 한 번 업데이트. 실패해도 세션 시작을 막지 않음.
language-rule.shUserPromptSubmit 매 프롬프트마다 언어 규칙 리마인더 주입 — 사용자 보고/대화는 한국어, 코드·주석·커밋 메시지는 English.
hooks.json플러그인 등록 weed-harness 플러그인이 설치될 때 등록되는 훅 선언. Codex 리뷰 훅 제거 후 현재는 빈 선언("hooks": {}) — 모든 훅은 /setup을 통한 opt-in 등록.
실제 등록 위치 — settings.json vs hooks.json

같은 스크립트라도 어디에 등록되느냐에 따라 적용 범위가 다릅니다.

  • settings.json (사용자 전역) — 모든 세션에 적용:
    • UserPromptSubmit language-rule.sh
    • SessionStart auto-update.sh (필수 스킬 자동 업데이트)
  • hooks.json (플러그인) — Codex 리뷰 훅 제거 후 빈 선언. 플러그인이 자동 등록하는 훅은 없음.
  • graphify-inject 훅은 /setup 스킬이 사용자 설정에 등록해 주는 방식입니다.

참고: 리포의 settings.json은 업스트림에서 vendored된 파일이라 /home/weed/ 경로가 남아 있습니다 — 로컬 설정 원본이 아닙니다.

🔄

훅이 만드는 자동화. 매 프롬프트마다 language-rule이 언어 규칙을 상기시키고, /graphify 실행 후에는 CLAUDE.md에 운용 섹션이 자동 주입됩니다. 세션이 시작될 때마다 auto-update가 필수 스킬(graphify claude+codex, superpowers, matt-*)을 자동으로 최신화합니다.
