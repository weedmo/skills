# matt-loop for Codex

This package exposes the matt loop (`matt-auto`, PR babysitting, routed conflict resolution, and the vendored Matt Pocock skills) for Codex and other supported agents.

Run `$matt-auto` to take an idea through Matt Pocock's main flow — grilling interview, spec, tracer-bullet tickets, per-ticket implementation; add `--dev` / `--main` / `--pr <base>` to also open a PR and shepherd it to merge-ready. Independent tickets run in parallel as Orca-orchestrated workers when available; `--parallel N` and `--on <env>` override concurrency and placement. Existing approval is reused; `--confirm` requests fresh review gates. Use `$pr-babysit` for one open PR and `$resolving-merge-conflicts` for an active merge/rebase conflict. Codex, OpenCode, and Claude Code route work by task tier automatically. On Codex, implementation uses the named Default/Deep roles and both final code-review axes use the independent Sol-only `matt-reviewer`; OpenCode and Claude Code use their packaged routing agents. Material decisions still escalate to the user. These skills depend on weed-harness (`$loop-report`, `$model-routing`, `$loop-gates`) — install it alongside matt-loop. The vendored skills remain directly invocable. Treat Claude-specific hooks, slash commands, or `~/.claude` paths as Claude-oriented guidance rather than a guaranteed Codex runtime feature.

This Codex package does not ship the repository's Claude hook automation.
