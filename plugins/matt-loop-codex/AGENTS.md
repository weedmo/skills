# matt-loop for Codex

This package exposes the matt loop (`matt-auto`, PR babysitting with routed conflict resolution, and the vendored Matt Pocock skills) for Codex and other supported agents.

Run `$matt-design` to design with the user using Matt Pocock's skills and write a local confirmed spec. On request it also renders the design discussed so far as a page; the page does not own design decisions or execution. Start execution separately with `$matt-auto --spec <path>`: this session implements and verifies each ticket in order, then runs QA and review by the other model family in parallel, with optional shipping. Add `--dev` / `--main` / `--pr <base>` to show the As-Is / To-Be page, open and shepherd a PR. Execution is autonomous by default; `--confirm` adds only a ticket-plan gate. Use `$pr-babysit` for one open PR or an active merge/rebase conflict (its `references/merge-conflicts.md`). Codex, OpenCode, and Claude Code route work by task tier automatically. The final pass runs `$qa-gate` and `$review-gate` in parallel, where the writer's other model family reviews on the route its rule table returns (`matt-reviewer-lite` Sol medium by default, `matt-reviewer` Sol high on risk); OpenCode and Claude Code use their packaged routing agents. Material decisions still escalate to the user. These skills depend on weed-harness (`$loop-report`, `$model-routing`, `$loop-gates`, `$review-gate`, `$qa-gate`) — install it alongside matt-loop. The vendored skills remain directly invocable. Treat Claude-specific hooks, slash commands, or `~/.claude` paths as Claude-oriented guidance rather than a guaranteed Codex runtime feature.

This Codex package does not ship the repository's Claude hook automation.
