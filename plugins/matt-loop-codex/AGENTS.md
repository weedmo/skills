# matt-loop for Codex

This package exposes the matt loop (`matt-auto`, PR babysitting, routed conflict resolution, and the vendored Matt Pocock skills) for Codex and other supported agents.

Run `$matt-auto` to take an idea through Matt Pocock's main flow — grilling interview, spec, tracer-bullet tickets, per-ticket implementation; add `--dev` / `--main` / `--pr <base>` to also open a PR and shepherd it to merge-ready. Independent tickets run in parallel as Orca-orchestrated workers when available; `--parallel N` and `--on <env>` override concurrency and placement. Existing approval is reused; `--confirm` requests fresh review gates. Use `$pr-babysit` for one open PR and `$resolving-merge-conflicts` for an active merge/rebase conflict. Codex, OpenCode, and Claude Code route these standalone workflows and matt-auto subagent work by task tier (model and reasoning effort) automatically. On Codex the skills use direct `spawn_agent` model/effort overrides; OpenCode and Claude Code use their packaged routing agents. Material decisions still escalate to the user. These skills depend on the weed-harness plugin's shared skills (`$loop-report` for the live progress page, `$model-routing` for the tier table, `$loop-gates` for unlazy-backed completion) — install weed-harness alongside matt-loop. The vendored skills (`$grill-me`, `$implement`, `$code-review`, ...) remain directly invocable for partial work. When a skill mentions Claude-specific hooks, slash commands, or `~/.claude` paths, treat that as Claude-oriented guidance rather than a guaranteed Codex runtime feature.

This Codex package does not ship the repository's Claude hook automation.
