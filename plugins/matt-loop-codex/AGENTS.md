# matt-loop for Codex

This package exposes the matt loop (`matt-auto`, PR babysitting, routed conflict resolution, and the vendored Matt Pocock skills) for Codex and other supported agents.

Run `$matt-design` to design with the user using Matt Pocock's skills and write a local confirmed spec. `$design-map` in weed-harness visualizes the design discussed so far as an artifact; it does not own design decisions or execution. Start execution separately with `$matt-auto --spec <path>`: tickets, implementation, verification, independent review and optional shipping. Add `--dev` / `--main` / `--pr <base>` to open and shepherd a PR. Independent tickets use Orca workers when available; `--parallel N` and `--on <env>` override placement. Execution is autonomous by default; `--confirm` adds only a ticket/plan review gate. Use `$pr-babysit` for one open PR and `$resolving-merge-conflicts` for an active merge/rebase conflict. Codex, OpenCode, and Claude Code route work by task tier automatically. On Codex, questions select the read-only `matt-answer` (Astra low) or `matt-answer-deep` (Astra xhigh) per question difficulty; implementation uses separate cost/time-aware roles and both final code-review axes use the independent Sol high `matt-reviewer` (Sol xhigh `matt-reviewer-deep` when Astra xhigh implemented any reviewed code); OpenCode and Claude Code use their packaged routing agents. Material decisions still escalate to the user. These skills depend on weed-harness (`$loop-report`, `$model-routing`, `$loop-gates`) — install it alongside matt-loop. The vendored skills remain directly invocable. Treat Claude-specific hooks, slash commands, or `~/.claude` paths as Claude-oriented guidance rather than a guaranteed Codex runtime feature.

For answer selection and continuity, read `skills/matt-auto/references/answer-routing.md`. A hard question can start on xhigh; the next easy question returns to low. This dispatches answer delegates, not a change to the parent session's model.

This Codex package does not ship the repository's Claude hook automation.
